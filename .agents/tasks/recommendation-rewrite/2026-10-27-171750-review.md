# RecommendationAgent Rewrite — LangGraph + StyleRAG + CriticAgent

This PR replaces the old MCP-based recommendation stack with a LangGraph StateGraph (7 nodes, ReAct trace), a TF-IDF style-guide RAG, and a LLM-as-a-Judge CriticAgent with a deterministic fallback. The orchestrator contract (`run(**kwargs) → {outfits:[{item_ids, relevance_score, explanation, ...}]}`) is preserved exactly. `recommendation_reasoning.py` and `mcp_client.py` are deleted; `recommendation_evaluation.py` is intact.

Watch for: **`NameError: json` in `_node_compose_outfit`** (confirmed) — the LLM path calls `json.loads(...)` but `json` is never imported at the module level; only `import json as _json` exists inside `_item_to_dict`. This crashes the LLM composition path at runtime the first time a real LLM is connected.

**Verdict**: NEEDS_CHANGES

---

## High-level view

All 6 tools exist with the correct `{tool_name, result, reasoning, error}` return shape. Pydantic input models are defined. Every tool falls back gracefully when `db is None`. `check_outfit_rules` is purely deterministic as required, and `_node_check_rules` correctly unwraps `result.get("result", {})` before storing `outfit_rules` in state, so `issues` reads correctly downstream.

`CriticAgent.evaluate()` returns `{scores:{meteo,occasion,couleurs,completude,fraicheur}, total, approved, feedback}` from both the LLM path and the deterministic fallback. The deterministic scoring covers all five criteria with correct branching. Approved threshold is `total >= 15` (out of 25).

`StyleRAG.retrieve()` works fully offline via TF-IDF fitted at `__init__` time on the hardcoded 20 French rules. The Qdrant path is gated behind a `try/except` import and silently degrades to TF-IDF. The fallback on any exception returns `STYLE_GUIDES[:top_k]`.

`RecommendationAgent.run()` accepts all orchestrator kwargs plus `city`, `db`, and `feedback_preferences`. It runs the graph `top_k` times, carries used item IDs across iterations, and falls back to a deterministic heuristic if any iteration's graph invocation fails. The `_fallback_outfit` correctly returns the required shape with all new fields present as empty/null.

The frontend `Outfit` interface has all existing fields intact and new agentic fields correctly typed as optional. `CollapsibleSection` has `accessibilityRole="button"`. Critic bar colors follow the `≥4→success`, `≥3→primary`, `<3→error` rule precisely.

One blocking bug: `json` is not imported at the module level in `recommendation_agent.py`, but `_node_compose_outfit` calls `json.loads(raw_text[start:end])` on the LLM response. This will raise a `NameError` whenever an LLM is connected and returns a parseable JSON string — exactly the success path. The fallback kicks in on the exception, so behavior degrades silently to deterministic composition rather than crashing the entire request, but the LLM compose path is permanently broken until fixed.

### Missing `import json` breaks the LLM compose path

Inside `_node_compose_outfit`, after calling `llm_agent._chat(...)`, the code does:

```python
parsed = json.loads(raw_text[start:end])
```

The module-level imports in `recommendation_agent.py` include no `import json` — only `import json as _json` inside `_item_to_dict` (a function body). Python function-local `import` statements do not place names in the enclosing module's namespace, so `json` is undefined at module scope. Every time a connected LLM returns a valid JSON string, this line raises `NameError: name 'json' is not defined`, the `except Exception` block catches it, logs a warning, and the outfit falls through to the deterministic `_compose_outfit_deterministic`. The fix is one line: add `import json` at the top of the file. **Confidence: confirmed** (verified via AST inspection — only alias import exists).

### `ReActStep` type / runtime shape mismatch (informational, not blocking)

`ReActStep.observation` is typed as `{tool: string; result: unknown}` in `recommendations.ts`, but the backend actually serializes observations as tool return dicts (`{tool_name, result, reasoning, error}`). The screen guards this with explicit casts (`as { result?: unknown }`), so there is no crash and `tsc --noEmit` passes. However, `step.observation.tool` will be `undefined` at runtime (the field is `tool_name`, not `tool`). This only affects the render if the observation's `tool` field were ever displayed — currently it isn't, so this is a latent type inconsistency rather than a user-visible bug. **Confidence: confirmed**.
