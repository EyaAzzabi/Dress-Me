# LangGraph RecommendationAgent + StyleRAG + CriticAgent rewrite

The rewrite replaces the old MCP-based recommendation pipeline with a LangGraph StateGraph (7 nodes, ReAct loop, Stylist+Critic iteration). StyleRAG provides TF-IDF retrieval over 20 hardcoded French style rules. CriticAgent evaluates outfits on a 5-criterion, 25-point grid with a deterministic fallback when no LLM is available. The orchestrator contract (`run(**kwargs) → {outfits:[...]}`) is preserved exactly. The two obsolete files (`recommendation_reasoning.py`, `mcp_client.py`) are deleted; `recommendation_evaluation.py` is intact.

Watch for: `complete` flag in `check_outfit_rules` is frozen before the color and season checks run (confirmed), so a structurally-complete but color-clashing outfit silently gets `complete=True` in the result dict. Routing is unaffected because it reads `issues`, but callers that read `result.complete` get a misleading value.

**Verdict**: APPROVED

---

## High-level view

All 6 tools exist and return the required `{tool_name, result, reasoning, error}` shape. The tools cover the full plan spec: `get_weather`, `search_wardrobe`, `filter_wardrobe`, `get_user_preferences`, `check_outfit_rules`, `record_feedback`.

`RecommendationAgent.run()` accepts the exact kwargs the orchestrator passes and returns `{"outfits": [{item_ids, relevance_score, explanation, ...}]}`. The graph runs `top_k` times, each iteration excluding items already used. A `try/except` around every `graph.invoke()` call falls back to a deterministic haut+bas+chaussures picker.

`StyleRAG.retrieve()` builds its TF-IDF matrix at `__init__` time with no I/O; it returns `STYLE_GUIDES[:top_k]` on any exception. Qdrant is an optional import gated in `try/except`. It works without Qdrant.

`CriticAgent.evaluate()` returns the required `{scores:{meteo,occasion,couleurs,completude,fraicheur}, total, approved, feedback}` shape. The LLM path validates all five keys before returning; any parse failure or missing key falls through to the deterministic scorer.

The `complete` field in `check_outfit_rules`'s result dict is computed before the color and season checks, so it only reflects structural completeness (categories). Color and season issues are still appended to `issues`, and routing reads `issues`, so graph flow is correct — but any caller reading `result["complete"]` directly sees a misleading `True` on a color-clashing or season-clashing outfit.

Frontend types are all optional on the new fields, so existing GET `/outfits` responses (which carry no agentic fields) do not break. `CollapsibleSection` has `accessibilityRole="button"`. Critic bar colors correctly apply `colors.success` for `value >= 4`, `colors.primary` for `value >= 3`, and `colors.error` below that.

### Six tools — return shape and coverage

All six tools are present and every return path uses `{"tool_name": str, "result": Any, "reasoning": str, "error": str | None}`. The confirmed coverage:

- `get_weather`: calls `WeatherService().get_current_weather(city)`; two fallback layers (service's own `_get_fallback_weather`, then a hardcoded `{"main":{"temp":20.0},...}` if even that raises).
- `search_wardrobe`: TF-IDF over `ClothingItem` text repr; returns `[]` with `error=None` when `db is None`.
- `filter_wardrobe`: SQLAlchemy with `ilike` on the JSON color column; tolerates `db is None`.
- `get_user_preferences`: `Counter` over styles and colors; last-10 feedback join; tolerates `db is None`.
- `check_outfit_rules`: deterministic. Returns `{complete, color_ok, issues}`. The `complete` flag bug is described in the Issues list.
- `record_feedback`: upsert with rollback on error; no-op if `db is None`.

### `complete` flag semantics gap in `check_outfit_rules`

Confirmed at line 322 of `recommendation_tools.py`: `complete = not issues` executes immediately after the category checks, before `color_ok` and `season_clash` are computed. Subsequent violations are added to `issues` but `complete` is never updated. The routing function `_route_check_rules` reads `rules.get("issues", [])`, so graph flow is correct. Any consumer of the returned dict that inspects `result["complete"]` directly — including future callers or tests — gets a misleading value for outfits that fail color or season constraints.

### ReAct graph — nodes, edges, and orchestrator contract

The seven nodes match the plan exactly. Conditional edges use `add_conditional_edges` with explicit routing dicts. The `_route_check_rules` function gates on `steps >= max_steps` (→ finalize) before checking `issues` (→ replan), preventing infinite loops. `_route_critic_evaluate` gates on `critic_iterations >= max_critic_iterations` (3), also preventing unbounded loops.

`run()` accepts all required kwargs including the new optional `city` and `db`. It runs the graph `top_k` times, resetting per-iteration working state while carrying `all_outfits` forward so later iterations exclude already-used items. The `except` block appends one deterministic fallback and breaks, ensuring the method always returns something.

`item_ids` in the output are `uuid.UUID` objects, matching the old agent's behavior. `relevance_score` is `critic_total / 25`, clamped to `0.5` when no critic score exists.

### StyleRAG without Qdrant

`StyleRAG.__init__` calls `_build_tfidf()` unconditionally, which fits a `TfidfVectorizer` on the 20-rule corpus in memory. `_init_qdrant` is only called when `qdrant_url` is passed. `retrieve()` has a double safety net: if `_vectorizer` is `None`, returns `STYLE_GUIDES[:top_k]`; if `cosine_similarity` raises, logs a warning and returns the same slice. Works offline.

### CriticAgent — LLM path and deterministic fallback

The LLM path calls `llm_agent._chat(messages, json_mode=True, timeout=10.0)`, which matches `LLMAgent._chat`'s signature (confirmed in `llm_agent.py`). It validates all five criterion keys before accepting the response; any missing key raises `ValueError` and falls through to `_deterministic_score`.

The deterministic scorer maps `weather_band` to expected seasons via `_WEATHER_BAND_SEASONS`, counts distinct colors, checks structural completeness, and counts overlap with `recent_item_ids`. All five criteria produce scores in 0–5; `approved = total >= 15` is consistent with the plan's threshold.

### Frontend types and accessibility

`recommendations.ts` adds `ReActStep` and `CriticScores` interfaces and extends `Outfit` with all five optional agentic fields. All existing fields (`id`, `item_ids`, `occasion`, `relevance_score`, `explanation`, `feedback`) are unchanged. The optional marker (`?`) ensures deserialization of DB-stored outfits (which have none of the agentic fields) does not raise.

`CollapsibleSection` is defined as a named function component above `OutfitCard`, uses `Pressable` with `accessibilityRole="button"`, and conditionally renders `collapsibleBody` based on `open` state.

Critic bar color logic in `OutfitCard`: `value >= 4 → colors.success`, `value >= 3 → colors.primary`, else `colors.error`. This matches the `≥4/≥3/<3` spec exactly.

### Deleted and preserved files

`recommendation_reasoning.py` and `mcp_client.py` no longer exist in `backend/app/agents/`. `recommendation_evaluation.py` is present. The orchestrator's `feedback_alignment_at_k` import remains importable.
